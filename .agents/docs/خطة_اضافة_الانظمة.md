## 1. المقدمة والرؤية الاستراتيجية

في المنظمات الكبرى، يقع الكثيرون في خطأ هندسي شائع وهو محاولة دمج كافة التفاصيل والوظائف في تطبيق واحد ضخم (Monolithic Architecture). هذا الأسلوب يؤدي مع الوقت إلى بطء النظام وصعوبة تطويره وتأثر المنظومة بالكامل في حال حدوث أي خطأ في قسم واحد.

**الرؤية الهندسية الحديثة المعتمدة في مشروعنا:**  
تحويل نظام **NEXUS TDS** إلى **منصة تشغيل مركزية (Enterprise Operating Hub)** تترابط معها المنظومات التخصصية (جرد الأصول، تتبع السويتشات والمنافذ، إدارة الطابعات، الموارد البشرية) كـ **أنظمة مساندة ذكية (Satellite Micro-Systems)** تتميز بالآتي:
* **الاستقلالية التامة:** المنظومة المساندة تعمل كخادم مستقل ولها واجهتها الخاصة، ويمكن استخدامها بمفردها تماماً.
* **الدمج البصري السلس:** الموظف المختص يجد المنظومة مدمجة في مساحة عمله اليومية دون الحاجة لفتح نوافذ متعددة أو تسجيل الدخول مرتين.
* **الاستفادة العكسية التلقائية:** تبادل البيانات الذكي بين التذاكر والمنظومات المساندة لتسريع حل الأعطال وتوثيق تاريخ الأجهزة للأبد.

## 2. إعادة هيكلة واجهة مود العمل (The Modular Workspace Shell)

تلبية لتوجيهات سعادتكم، لن تكون شاشة مود العمل (`/ops`) صفحة ثابتة ومكدسة لحوض التذاكر فقط، بل سيتم تحويلها إلى **بيئة عمل مؤسسية نموذجية بشريط جانبي نحيف وفاخر (Sleek Sidebar)**:

```
+--------------------------------------------------------------------------------------------------+
| NEXUS TDS - MODULAR ENTERPRISE WORKSPACE SHELL                                                  |
+----+---------------------------------------------------------------------------------------------+
|    |                                                                                             |
| [N]|  [ مساحة العمل الرئيسية المعروضة ]                                                           |
|    |                                                                                             |
| 📁 |  1. عند النقر على (أيقونة الطلبات والعمليات 📁):                                            |
|    |     - يظهر حوض التذاكر المفتوحة بكامل أشكاله (الشريط الأفقي المتمدد لـ 7 صفوف + القائمة)     |
|    |     - محرك البحث والفلاتر الذكية وإحصائيات الحوض التفاعلية                                  |
| 🖥️ |     - تقارير الإنجاز وتحليلات الأداء ونافذة فحص التذاكر المركزية (Bento Inspection Modal)   |
|    |                                                                                             |
| 🏢 |  2. عند النقر على (أيقونة منظومة جرد الأصول 🖥️) [تظهر فقط للمصرح لهم]:                    |
|    |     - تفتح واجهة منظومة جرد الأصول التقنية مباشرة في نفس الشاشة بكامل أدواتها وسجلاتها      |
| ⚙️ |                                                                                             |
|    |  3. عند النقر على (أيقونة الموارد البشرية 🏢) [تظهر فقط لموظفي HR]:                         |
| 👤 |     - تفتح منظومة الموظفين والإجازات في نفس البيئة دون تشتيت                                 |
|    |                                                                                             |
+----+---------------------------------------------------------------------------------------------+
```

### الفوائد التشغيلية المباشرة:
1. **تجميع مركز العمليات:** جميع أدوات التذاكر والتحليلات والتقارير الحالية تنضوي تحت أيقونة رئيسية واحدة، لتكون الشاشة في غاية النظام والصفاء الذهني.
2. **التوسع اللامحدود:** عندما يجهز نظام تتبع السويتشات، أو نظام الطابعات، أو نظام الموارد البشرية، يُضاف النظام كأيقونة فرعية في الشريط فوراً وبدون أي إعادة هيكلة.
3. **انعدام وقت الانتظار (No Page Reload):** التبديل بين التذاكر وجرد الأصول يتم بلمح البصر دون أي إعادة تحميل للصفحة.

## 3. حوكمة الصلاحيات الفردية والمؤسسية (3-Tier Access Matrix)

أشرتم سعادتكم بدقة إلى ضرورة التحكم الإداري: *"في موظفين في الدعم الفني ما نبيش نضيف لهم سيستم جرد الأصول، وفي موظفين نبي نضيف لهم... ومستقبلاً أنظمة لموظفي الموارد البشرية"*.

لتحقيق ذلك بنسبة 100%، تم تصميم **مصفوفة تحكم ثلاثية الأبعاد في شاشة الإدارة**:

1. **المستوى الأول (تخصيص الإدارات - Departments):**  
   تحديد الإدارة التي يتبع لها النظام (منظومة الأصول تتبع إدارة تقنية المعلومات، ومنظومة الإجازات تتبع الموارد البشرية).
2. **المستوى الثاني (تخصيص الأدوار - Roles):**  
   تحديد الأدوار المسموح لها داخل الإدارة (الفنيين والمشرفين فقط، واستثناء المتدربين).
3. **المستوى الثالث وهو الأهم (التحكم الفردي بالموظفين - Per-User Matrix):**  
   شاشة مخصصة لمدير النظام تعرض جدولاً بأسماء موظفي القسم، وبجانب كل اسم مفتاح تفعيل/تعطيل:
   * *أحمد (دعم فني): مفعّل له نظام الأصول ✅*
   * *سالم (دعم فني): غير مفعّل له ❌ (تختفي الأيقونة من شاشته تماماً).*

## 4. مرونة الربط الشبكي ونقل السيرفرات (Dynamic Reverse-Proxy Gateway)

للإجابة عن تساؤلكم المحوري: *"لو نقلنا المنظومة لسيرفر آخر، أو جهاز زميل، أو خارج الشبكة، كيف نضمن عدم انكسار النظام ويبقى التعديل بسيطاً؟"*

### آلية العمل الهندسية:
1. **انعدام العناوين الثابتة في الكود (Zero Hardcoded IPs):**  
   واجهة المتصفح لا تتصل بأي سيرفر خارجي مباشرة، بل تتصل بمسار محلي موحد: `/api/v1/satellites/inventory/*`.
2. **حقل عنوان السيرفر في شاشة الإدارة (Configurable Target Base URL):**  
   تعديل مكان المنظومة يتم من لوحة الإدارة بحقل واحد بسيط:
   * حالياً في الاختبار المحلي: `http://localhost:3000`
   * غداً على جهاز زميلك في الشبكة: `http://192.168.1.85:3000`
   * مستقبلاً على سيرفر سحابي أو مركزي: `https://inventory.litc.ly`
3. **التحديث الفوري بصفر كود (Zero-Downtime):**  
   بمجرد الضغط على "حفظ" في لوحة الإدارة، يوجه خادم نظامنا (TDS Backend) كافة الطلبات للعنوان الجديد فوراً دون الحاجة لإعادة تشغيل النظام أو تعديل أي ملف برمجي.
4. **صمام الأمان وفحص الاتصال الحي (Circuit Breaker & Live Ping):**  
   إذا تم إطفاء سيرفر المنظومة لأي سبب، يظهر للموظف تنبيه أنيق: *"خادم منظومة الأصول قيد الصيانة حالياً"* وتظل بقية التذاكر تعمل بكامل طاقتها.

## 5. الأمن السيبراني وتأمين المنظومة (Enterprise Cybersecurity Standards)

وفقاً لأحدث المعايير العالمية لعام 2026 (OWASP Top 10 ومعمارية انعدام الثقة Zero-Trust):

### 1. الحماية الصارمة من هجمات تزوير الطلبات بالخادم (SSRF Protection - OWASP A01):
* **الخطر:** محاولة مخترق كتابة عنوان خبيث في حقل السيرفر لاختراق خوادم المؤسسة أو سحب ميتاداتا السحابة (`169.254.169.254`).
* **الحماية:** فحص العنوان والتأكد من البروتوكولات المسموحة (`http/https`)، وحظر أي نطاقات ميتاداتا سحابية مشبوهة، والتحقق من الـ DNS قبل إرسال أي طلب.

### 2. العزل البصري الآمن للحاوية (Strict Sandboxed Iframe - OWASP A03):
* **الخطر:** إذا حدث اختراق للمنظومة المساندة، قد تحاول قراءة شاشة التذاكر أو سرقة كوكيز الموظف في النظام الرئيسي.
* **الحماية:** تشغيل المنظومة داخل حاوية معزولة ومحصنة بخاصية `sandbox="allow-scripts allow-forms"` وحظر الوصول إلى النافذة الأبوية (`No DOM Access`)، مما يجعل اختراق النظام الرئيسي مستحيلاً برمجياً.

### 3. جسر التوكنات المؤقتة والدخول الموحد (Ephemeral Token Exchange - RFC 8693):
* **الخطر:** كشف التوكن الرئيسي للموظف أو تسريب كلمات المرور بين الخوادم.
* **الحماية:** نظام TDS لا يرسل التوكن الرئيسي أبداً؛ بل يُنشئ "توكن تفويض مؤقت وصغير" بصلاحية 60 ثانية فقط مخصص لمنظومة الأصول. تتبادله المنظومة مع الخادم وتمنح الموظف جلسة مستقلة دون أي خطر تسريب لحسابه الرئيسي.

### 4. سياسة انعدام الثقة والتحقق المستمر (Zero-Trust Enforcement):
* **الخطر:** قيام موظف غير مصرح له أو تم فصله بإرسال طلبات للمنظومة المساندة.
* **الحماية:** يتم التحقق من هوية وصلاحية الموظف في كل طلب يمر عبر البوابة، فإذا سحب الأدمن الصلاحية منه الآن، يتوقف اتصاله بالمنظومة في نفس اللحظة فوراً.

### 5. سجل التدقيق والتتبع الأمني (Audit Logging & SIEM):
* توثيق كل حركة، وكل عملية دخول، وكل استعلام عن جهاز، مع تسجيل رقم الموظف، والتاريخ والوقت بدقة، ورقم المعاملة المرتبطة.

## 6. الاستفادة العكسية في التذاكر ودورة حياة الأصل (Bidirectional Intelligence)

1. **التلميح الذكي في التذكرة (Downstream Hint):**  
   عند فتح تذكرة دعم فني لصيانة طابعة في "الإدارة التجارية"، يظهر للفني كارت ذكي يقترح الطابعات المخصصة للإدارة التجارية أو حاسوب الموظف المسجل مع زر "ربط الأصل بالتذكرة" بضغطة واحدة.
2. **المزامنة العكسية عند إغلاق التذكرة (Upstream Sync):**  
   عند إتمام الصيانة وإغلاق التذكرة في نظام TDS، يُرسل النظام تقريراً آلياً لمنظومة الجرد ليُسجل في جدول التاريخ (`device_history`):  
   *(رقم المعاملة REQ-0062 • تاريخ ووقت الصيانة • اسم الفني • وصف العطل والإجراء المتخذ)* لتكتمل دورة حياة الأصل دون أي تدخل يدوي.

| :--- | :--- | :--- |
| **المرحلة 1** | **بناء الشريط الجانبي الفاخر في مود العمل (`WorkModeShell`)** | تجميع كافة أدوات التذاكر والعمليات تحت أيقونة واحدة "مركز العمليات والطلبات"، وإضافة أيقونة ثانية لـ "منظومة جرد الأصول". |
