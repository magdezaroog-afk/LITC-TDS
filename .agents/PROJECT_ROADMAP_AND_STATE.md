### 1. نبذة تعريفية عن المشروع (System Overview)
* **اسم النظام:** NEXUS TDS (Ticketing Dynamic System).
* **طبيعة النظام:** نظام ERP ومحرك ديناميكي متقدم لإدارة وتوجيه تذاكر ومهام العمل المؤسسية، وحوكمة مسارات العمل، ومتابعة الأداء، والتحليلات والمفاضلات التشغيلية.
* **البيئة التقنية:**
  * **الواجهة الأمامية (Frontend):** React 19 + TypeScript + Vite + Kitchn UI + Framer Motion + Lucide React + Tailwind Merge.
  * **الخلفية (Backend):** Node.js + Express + TypeScript + Prisma ORM + Redis Session Store.
  * **قواعد البيانات:** SQL Server / SQLite عبر Prisma Client.
  * **الهوية البصرية:** اللون البترولي المؤسسي العميق (`#135d79`) مع اللون البرتقالي الحيوي المعتمد (`#f36c21`)، وضع ليلي ونهاري فاخر مع تأثيرات الزجاج والظلال الناعمة.

### 2. البنية المعمارية الأساسية للبيانات (Core Architectural Entities)

```
┌────────────────────────────────────────────────────────────────────────┐
│                      نظام NEXUS TDS المؤسسي                            │
├───────────────────────────────────┬────────────────────────────────────┤
│   🏛️ الهيكل المؤسسي الشامل للشركة │   ⚙️ الهيكل التشغيلي لمعالجة الطلب │
│   (Institutional Org Structure)   │   (Operational Service Structure)  │
├───────────────────────────────────┼────────────────────────────────────┤
│ • مصدره: LITC_ORG_TREE_SNAPSHOT   │ • مصدره: جداول Department / Team   │
│ • يشمل: مجلس الإدارة، المكاتب،    │ • يشمل: إدارة تقنية المعلومات،     │
│   الإدارة الفنية، المالية،        │   قسم الدعم الفني، فريق الطابعات،  │
│   التجارية، والموارد البشرية.     │   فرق الصيانة والعمليات.           │
│ • دوره: منه يخرج الموظفون الطالبون│ • دوره: الفرق التي تستلم وتعالج    │
│   للخدمات، وإليه تُنسب مقارنة     │   الطلبات، وبناءً عليها تُقاس      │
│   كثافة الطلبات في التحاليل.      │   مؤشرات الكفاءة والـ SLA.        │
└───────────────────────────────────┴────────────────────────────────────┘
```

* **المباني والمواقع:** مصدرها الوحيد والحصري هو جدول `SystemReference` ذو الحالة النشطة (`isActive: true`). لا وجود لأي مبانٍ وهمية أو قديمة في النظام.
* **مسارات العمل (Routes):** مخزنة في إعدادات النظام `litc_ticket_routes`، ويحدد الآدمن لكل مسار:
  * الجهة المستلمة (القسم أو الفريق المكلف).
  * حقول النموذج والمستدلات المربوطة (`routeDynamicFields`).
  * التفرعات الشرطية للمستدلات (`childBindings`).
