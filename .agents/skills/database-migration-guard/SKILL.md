# مهارة حوكمة وسلامة قواعد البيانات (Database Migration Guard)

## 1. طبيعة عمل المهارة
* **نمط التشغيل:** **تلقائي إلزامي (Autonomous)** قبل أي تعديل على `schema.prisma` أو تنفيذ أوامر ترحيل قواعد البيانات.
* **النطاق:** Prisma ORM, PostgreSQL, SQLite, MySQL وكافة محركات قواعد البيانات المؤسسية.

---

## 2. القواعد الصارمة لإدارة المخططات (Schema Governance)
1. **منع التعديلات التخريبية المباشرة:** يُحظر تنفيذ `prisma db push --accept-data-loss` في بيئات الإنتاج أو البيئات المتصلة ببيانات حقيقية.
2. **فحص العلاقات والمفاتيح الأجنبية:** عند إضافة أي نموذج (Model)، يجب التحقق من قيود الحذف والترابط (`onDelete: Cascade` أو `SetNull` أو `Restrict`) لمنع ترك سجلات يتيمة.
3. **فهرسة حقول الاستعلام الشائعة (Mandatory Indexes):**
   - أي حقل يتم البحث به بانتظام (مثل `nationalId`, `trackingNumber`, `status`, `createdAt`, `userId`) يجب أن يحمل وسم `@@index([fieldName])` أو `@unique`.
4. **تشفير الحقول الحساسة:** الحقول فائقة السرية (مثل البيانات البيومترية، كلمات المرور المؤقتة، الملاحظات الأمنية) تُشفر برمجياً بخوارزمية `AES-256-GCM` قبل التخزين.

---

## 3. مسار عمل الترحيل الآمن (Safe Migration Protocol)
عند الحاجة لتعديل المخطط:
1. مراجعة التغيير في `prisma/schema.prisma`.
2. إنشاء ملف الترحيل دون تطبيقه لفحصه أولاً:
   ```bash
   npx prisma migrate dev --create-only --name <migration_name>
   ```
3. فحص ملف الـ SQL الناتج والتأكد من عدم وجود أوامر `DROP TABLE` أو `DROP COLUMN` غير مقصودة.
4. تطبيق الترحيل وتحديث عميل Prisma:
   ```bash
   npx prisma migrate deploy
   npx prisma generate
   ```

---

## 4. قائمة الفحص قبل الاعتماد (Checklist)
- [ ] هل المخطط يحتوي على كافة الفهارس المطلوبة للاستعلامات السريعة؟
- [ ] هل تم اختبار الاستعلام في مسار الـ API للتأكد من خلوه من أخطاء الـ Null Pointer؟
- [ ] هل تم تحديث الأنواع (Types) المتولدة من Prisma في الواجهة الأمامية والباك-إند؟
