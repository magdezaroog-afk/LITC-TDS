2 Unified Corporate Identity via Microsoft Entra ID (M365 SSO)

M

Enterprise Single Sign-On Architecture (Microsoft Entra ID / M365)

Native Integration with LITC Official Domain (@litc.ly)

The PMO officially highlights that NEXUS TDS identity governance is architected for native federation with LITC's central identity provider via Microsoft Entra ID (Azure AD / M365) utilizing standard OpenID Connect (OIDC) / OAuth 2.0 protocols for all corporate domain accounts (@litc.ly).

1. Conditional Access Governance

Every authentication attempt is subject to LITC cloud security policies (geographic fencing, device compliance health, and anomalous IP blocking).

2. Mandatory Multi-Factor Authentication (MFA)

Enforcement of two-factor verification via Microsoft Authenticator app, standardizing security across all company employees without third-party exposure.

3. Zero Local Password Storage Risk

NEXUS TDS servers neither accept nor store plain passwords for corporate users; identity tokens are cryptographically signed and issued by Microsoft.

4. Fail-Safe Emergency Authentication

An isolated internal fail-safe engine powered by Argon2id and protected by a 3-attempt account lockout guard provides operational continuity during external outages.

3 The Six Active Cyber Defense Perimeters in Code

NEXUS TDS enforces a strict Zero-Trust Architecture via six layered defensive controls operating 24/7:

Perimeter 1
In-Memory Application Firewall (Software WAF)
Implementation: src/backend/security/WAFMiddleware.ts
• Instantaneous $O(1)$ memory regex inspection of query, params, and payload.
• Absolute mitigation of SQL Injection (SQLi), Cross-Site Scripting (XSS), and Path Traversal.
• Dynamic IP and payload blacklist synchronization across instances via Redis channels.
Perimeter 2
Sovereign Rate Limiter & Security Headers
Implementation: src/expressApp.ts
• Mitigation of DoS/DDoS via strict 150 req/min limit per source IP.
• Real-time SSE streams throttled to 30 conn/min to prevent Event Loop memory exhaustion.
• Helmet security suite enforcing strict Content Security Policy (CSP) and Clickjacking protection.
Perimeter 3 (LITC 13-1-خ Aligned)
3-Attempt Account Lockout & Instant Revocation
Implementation: src/backend/controllers/AuthService.ts & RedisClient.ts
• Policy 13-1-خ: Automatic 30-minute lockout triggered at exactly 3 consecutive failed login attempts.
• Instant Revocation Blacklist: Logout instantly records SHA-256 token digests in Redis to nullify compromised JWTs in sub-milliseconds.
Perimeter 4 (LITC 13-1-ح Aligned)
15-Minute Inactivity Session Guard
Implementation: src/components/infrastructure/InactivitySessionGuard.tsx
• Policy 13-1-ح: Automatic termination and Redis token revocation upon 15 minutes of user inactivity.
• Luxury glassmorphic modal with a 60-second countdown at minute 14 offering session renewal or secure logout.
Perimeter 5
Inter-System Protocol Guard (UECP Gateway)
Implementation: src/backend/security/UECPMiddleware.ts
• Cryptographic payload signing via HMAC-SHA256.
• Constant-time comparison (crypto.timingSafeEqual) eliminating timing attack vectors.
• Replay attack prevention using X-Idempotency-Key stored in Redis for 24 hours.
Perimeter 6
Immutable Non-Repudiation Audit Logs (SIEM)
Implementation: src/backend/services/ImmutableLogService.ts & SIEMLogger.ts
• Event logging in dedicated SecurityEventLog table immune to programmatic tampering or deletion.
• Event classification into 4 official LITC tiers: Critical, High, Medium, Low.
• Asynchronous non-blocking batch flusher dispatching events every 5 seconds.
